# 易用性功能计划

分支：`feat/convenience`

目标：让日常用起来少走几步。原则不变：dsh 一行不改，安装包保持轻量。

按顺序一条一条做，每条做完单独验证、单独提交。

## 1. 在文件夹上「用 dsh 打开」

**现状**：在某个项目里开会话，要先打开应用、点添加工作区，再在目录选择器里一层层找到文件夹。第二次启动时，`src-tauri/src/main.rs` 里 single-instance 回调拿到了 `_argv` 和 `_cwd`，但直接丢掉了，只做了 `reveal`。

**要做的**：

- 核心：把一个文件夹路径交给正在运行的 dsh，dsh 建好（或复用）对应的工作区，页面跳过去。
- 入口（核心打通后再加）：
  - 命令行 `dsh-desktop <路径>`，`.` 表示当前目录
  - 把文件夹拖到任务栏图标上
  - 资源管理器 / 访达 / 文件管理器的右键菜单「用 dsh 打开」

**可行性**：dsh 的 workspace controller 有 `createWorkspace({ path })`，同一路径会复用已有工作区。

**待确认**：

- 工作区建好之后，怎么让 dsh 页面切到它的会话。要看 dsh 前端有没有能直接用的跳转入口。
- 冷启动（应用还没开）时带着路径启动，要等 dsh 起来以后再执行。
- 右键菜单在三个平台各自怎么注册，卸载时要清理干净。

**完成标准**：在任意文件夹上执行 `dsh-desktop .`，不管应用开着没开，都会进到这个文件夹的工作区；同一个文件夹打开两次，不会出现两个工作区。

## 2. 托盘菜单里的最近工作区

**要做的**：托盘菜单（以及 Windows 任务栏跳转列表）里列出最近用过的几个工作区，点一下直接跳过去。

**依赖**：第 1 条的「打开某个工作区」。

**待确认**：最近工作区的列表从哪里取（dsh 的 workspace 投影，还是桌面端自己记），以及多久刷新一次。

## 3. 托盘和任务栏图标显示状态

**现状**：窗口收进托盘后，看不出 dsh 在干什么。`src-tauri/src/signal.rs` 已经能拿到「回合结束」和「等待确认」，目前只用来发通知。

**要做的**：

- 有回合在跑时，托盘图标显示忙碌
- 等待确认时，图标上加一个角标
- Windows 任务栏图标加一个状态标记（overlay icon）

**完成标准**：窗口不在前台时，看一眼图标就知道 dsh 是空闲、在跑，还是在等你。

## 4. 全局快捷键呼出窗口

**要做的**：按一个全局快捷键（暂定 `Ctrl+Shift+D` / `Cmd+Shift+D`）显示或隐藏窗口。

**待确认**：默认用哪个组合键、要不要能改、和别的软件冲突时怎么处理。

## 5. 记住窗口大小和位置

**现状**：`src-tauri/src/main.rs` 里窗口每次都按 1360×900 打开。

**之前的问题**：以前做过一次，启用后窗口会闪一下。原因多半是窗口先按默认尺寸显示，再挪到保存的位置。

**要做的**：在窗口创建、还没显示之前定好尺寸和位置，不能先显示再挪。保存下来的位置如果落在已经拔掉的显示器上，要退回默认值。

**完成标准**：用截图逐帧确认启动时不闪。

## 待定：开屏动效

还没决定要不要做，评估见下。

- dsh 网页端本身没有开屏动效。我们这个应用只有一个窗口，从托盘呼出不会重新加载页面。所以能放动效的地方只有冷启动时的加载页 `dist/index.html`，现在那里已经有一个 420ms 的入场动画和一个转圈。
- **只在冷启动加载页做**：这段时间本来就在等 dsh 起来，动效不会额外拖慢启动；dsh 一就绪就要立刻切走，不能为了把动画播完而让人多等。
- **不做「每次打开窗口都播一遍」**：从托盘呼出本来是瞬间的事，加动效只会变慢。
- **性能**：只动 `transform` / `opacity` 的 CSS 动画几乎不占资源；粒子、canvas、WebGL、大面积 blur 这类就不划算，尤其冷启动时 Node 正在抢 CPU。继续遵守 `prefers-reduced-motion`。
- 结论：优先级排在上面五条之后。要做的话，先拿到具体参考效果再评估。
