## 1. 在文件夹上「用 dsh 打开」

**目标**：在某个项目里开会话，原来要先打开应用、点添加工作区，再在目录选择器里一层层找到文件夹。现在把路径交给应用，就直接进到那个文件夹的工作区。

**完成标准**：在任意文件夹上执行 `dsh-desktop .`，不管应用开着没开，都会进到这个文件夹的工作区；同一个文件夹打开两次，不会出现两个工作区。

### 已完成：核心通路 + 命令行入口

提交：`e30ed0f`、`f91f724`

- `dsh-desktop <路径>`：冷启动从 `std::env::args` 读，应用已在运行时由 single-instance 回调把参数和当前目录转过来。相对路径按启动时的目录解析；传入文件就打开它所在的文件夹；不存在的路径忽略。
- 桌面端进不去 dsh 前端，真正打开工作区的是随包插件 `dsh-desktop-signal`（`plugin/lib/client.js` 的 `openFolder`）：
  - `ctx.workspaces.create({ path })`：同一路径复用已有工作区；成功直接返回工作区对象，失败抛异常（不是 `{ ok, value }`）。
  - `ctx.uiWorkspace.openWorkspace(id)`：侧边栏自己用的那条路，复用空会话或新建一个，再切过去。
  - 两个服务在子 scope 里等，不是硬依赖；就绪后发 `folder-ready`，成功发 `folder-opened`，失败发 `folder-failed`。
- `src-tauri/src/folder.rs`：把路径存着，等 `folder-ready` 再交出去；页面开始跳转就当插件没就绪。失败提示只在确实交出过路径时才弹，防止页面脚本伪造消息弹框。
- 插件不在时弹对话框，同一个请求只问一次：
  - 被安全模式搁置 →「重新加载插件」
  - 没装 →「打开插件面板」（不在对话框里直接装：只允许从插件面板装插件，防止页面脚本触发安装）
  - 路径会留着，插件回来后接着打开；点取消就丢掉。

**已验证**（Windows，dsh 0.2.0-rc.2）：冷启动带路径、运行中带路径、同一文件夹打开两次、传文件、相对路径、路径不存在、窗口在托盘里、插件不在（装回后接着打开 / 取消后不打开）。

**已知限制**：

- dsh 太旧、没有 `uiWorkspace` 服务时，路径会一直存着，不打开也不提示。
- 开发模式下 `tauri dev` 会把工作目录切到 `src-tauri`，所以 `npx tauri dev -- -- .` 里的 `.` 指的是 `src-tauri`。正式版不受影响。

### 顺带修掉的：从插件面板装不上「会话信号」

提交：`a5afb73`。原来就有的 bug，测「插件不在」时撞上的。

- `plugins.rs` 的 `local_spec` 在 Windows 上会给本地插件路径加引号，原本是给老版本 dsh 用的（它经过 `cmd.exe` 调 pnpm）。
- dsh 0.2 改用 `execa` 直接传参，引号被原样传给 pnpm，被当成相对路径，装不上。
- 现在只有路径里有空格时才加引号。剩下一种情况没修：Windows 用户名带空格 + 新版 dsh。要修得先判断 dsh 版本。

### 未做：其他入口

- 资源管理器 / 访达 / 文件管理器的右键菜单「用 dsh 打开」

都复用上面的通路，只是入口不同。待确认：三个平台各自怎么注册；卸载时要清理干净。右键菜单不随插件在不在而增删：Windows 能做到，访达和 Linux 很别扭，安全模式下还会来回变。

### 手动测试注意

仓库目录带「低完整性」标记，在仓库里编出来的 exe 会以低完整性运行，写不了 `~/.dsh`。手动测试时要把编译输出放到仓库外：

```powershell
$env:CARGO_TARGET_DIR = "C:\Users\EDY\dsh-desktop-target"
npx tauri dev -- -- C:\tmp\dsh-a
```

第二次启动用 `C:\Users\EDY\dsh-desktop-target\debug\dsh-desktop.exe <路径>`。

## 2. 托盘菜单里的最近工作区

**要做的**：托盘菜单（以及 Windows 任务栏跳转列表）里列出最近用过的几个工作区，点一下直接跳过去。

**依赖**：第 1 条的「打开某个工作区」。

### 已完成

提交：`4fd9861`

- 列表由插件从 dsh 算（`plugin/lib/client.js` 的 `watchRecent`），不是桌面端自己记：
  - 工作区本身没有「上次使用时间」，`updatedAt` 改名、排序时也会变。所以按工作区里最新会话的 `updatedAt` 排序（dsh 每条消息都会更新它）；会话不在列表里时，用工作区自己的时间兜底。
  - 取前 5 个。工作区列表或会话列表一变就重算，但只有标题、路径或顺序变了才发 `recent` 事件，不会跟着流式输出一直发。
- `src-tauri/src/recent.rs`：
  - 托盘菜单最上面一个「最近工作区」标题加 5 行，点了走和 `dsh-desktop <路径>` 相同的 `folder::open`。不写盘：dsh 起来之前托盘里没有这几行；dsh 重启期间保留旧列表，这时点击会等插件就绪。
  - 标题超过 40 字截断；`&` 写成 `&&`，否则会被菜单当成助记符。
  - Windows 跳转列表：`ICustomDestinationList`，每行是 `dsh-desktop.exe "<路径>"` 的快捷方式，在单独线程里写。
  - AUMID：安装版启动时用 `SetCurrentProcessExplicitAppUserModelID` 设成 bundle id，跳转列表也用这个 id，和开始菜单快捷方式、toast 一致（`toast::app_id`）。不这样做的话，从开机自启或终端启动的进程挂不到同一个任务栏按钮上。在 `target\debug` / `target\release` 里直接跑的构建不设。

**已验证**（Windows，dsh 0.2.0-rc.2）：托盘菜单出现最近工作区，点了能跳过去；任务栏右键有「最近工作区」分组，点了能跳过去。

**踩过的坑**：

- 跳转列表行的标题（`PKEY_Title`）必须用 COM 分配器（`SHStrDupW`）分配，再 `PropVariantClear`。用自己的内存会导致堆损坏。
- 快捷方式的 exe 路径要用 `std::env::current_exe()`。`tauri::utils::platform::current_exe()` 返回 `\\?\C:\…`，`IShellLinkW::SetPath` 不接受，报 `E_INVALIDARG`。
- 调试版是控制台程序，在任务栏上会多出一个控制台按钮。这个按钮不带我们的 AUMID，所以单独成一组。正式版没有控制台窗口。

## 3. 托盘和任务栏图标显示状态

**现状**：窗口收进托盘后，看不出 dsh 在干什么。`src-tauri/src/signal.rs` 已经能拿到「回合结束」和「等待确认」，目前只用来发通知。

**要做的**：

- 有回合在跑时，托盘图标显示忙碌
- 等待确认时，图标上加一个角标
- Windows 任务栏图标加一个状态标记（overlay icon）

**完成标准**：窗口不在前台时，看一眼图标就知道 dsh 是空闲、在跑，还是在等你。

### 已完成

提交：`84a6788`（以及 `5598c55`，见下）

- 插件在每次计数变化时发 `status` 事件，带 `running`（`running` 为真的会话数）和 `waiting`（等待中的会话数）。首次快照也会发，所以页面在一轮进行到一半时加载，图标也能立刻显示忙碌。某一半的 scope 销毁时，它那份计数归零。
- `src-tauri/src/status.rs`：三种外观。空闲是原图标；在跑时右下角加蓝点；等待确认时加橙点，橙点优先于蓝点。圆点带白边，按像素覆盖率做抗锯齿，16px 下看着也是圆的。不做动画：转圈需要一个定时器一直重画。
  - 托盘图标、托盘 tooltip 第二行（「正在运行」/「在等你回应」）、Windows 任务栏 overlay，三处一起更新。
  - 页面开始跳转时回到空闲：报计数的插件随文档一起没了。

**顺带修掉的**（`5598c55`）：dsh 0.2 去掉了 `uiSession.pendingInteractions`，等待项改放在 `uiSession.sessionStatus` 每一行的 `pendingInteraction` 字段里，对象本身没变。插件原来只读旧字段，所以在 dsh 0.2 上，等待确认的通知和通知上的「允许 / 拒绝」按钮一直不工作。现在由 `pendingOf` 两种都兼容。

**已验证**（Windows，dsh 0.2.0-rc.2）：跑任务时托盘图标出现蓝点；等待批准时托盘出现橙点，任务栏 overlay 也是橙色，tooltip 显示「在等你回应」，并弹出带按钮的系统通知；批准后这一轮跑完，圆点消失。

## 5. 记住窗口大小和位置

**现状**：`src-tauri/src/main.rs` 里窗口每次都按 1360×900 打开。

**之前的问题**：以前做过一次，启用后窗口会闪一下。`main.rs` 里 `.center()` 上面的注释写了原因：窗口先建好，再挪到保存的位置，用户会看到它跳一下。

**要做的**：在窗口创建、还没显示之前定好尺寸和位置，不能先显示再挪。保存下来的位置如果落在已经拔掉的显示器上，要退回默认值。

**完成标准**：用截图逐帧确认启动时不闪。

## 待定：开屏动效

还没决定要不要做，评估见下。

- dsh 网页端本身没有开屏动效。我们这个应用只有一个窗口，从托盘呼出不会重新加载页面。所以能放动效的地方只有冷启动时的加载页 `dist/index.html`，现在那里已经有一个 420ms 的入场动画和一个转圈。
- **只在冷启动加载页做**：这段时间本来就在等 dsh 起来，动效不会额外拖慢启动；dsh 一就绪就要立刻切走，不能为了把动画播完而让人多等。
- **不做「每次打开窗口都播一遍」**：从托盘呼出本来是瞬间的事，加动效只会变慢。
- **性能**：只动 `transform` / `opacity` 的 CSS 动画几乎不占资源；粒子、canvas、WebGL、大面积 blur 这类就不划算，尤其冷启动时 Node 正在抢 CPU。继续遵守 `prefers-reduced-motion`。
- 结论：优先级排在上面五条之后。要做的话，先拿到具体参考效果再评估。
